Manifest

Manifest file format

Stay organized with collections

Save and categorize content based on your preferences.

Every extension must have a manifest.json file in its root directory that
lists important information about the structure and behavior of that extension.
This page explains the structure of extension manifests and the features they
can include.

Examples

The following example manifests show the basic manifest structure and some
commonly used features as a starting point for creating your own manifest:

Minimal manifest{
"manifest_version": 3,
"name": "Minimal Manifest",
"version": "1.0.0",
"description": "A basic example extension with only required keys",
"icons": {
"48": "images/icon-48.png",
"128": "images/icon-128.png"
}
}

Register a content script{
"manifest_version": 3,
"name": "Run script automatically",
"description": "Runs a script on www.example.com automatically when user installs the extension",
"version": "1.0",
"icons": {
"16": "images/icon-16.png",
"32": "images/icon-32.png",
"48": "images/icon-48.png",
"128": "images/icon-128.png"
},
"content_scripts": [
{
"js": [
"content-script.js"
],
"matches": [
"http://*.example.com//"
]
}
]
}

Inject a content script{
"manifest_version": 3,
"name": "Click to run",
"description": "Runs a script when the user clicks the action toolbar icon.",
"version": "1.0",
"icons": {
"16": "images/icon-16.png",
"32": "images/icon-32.png",
"48": "images/icon-48.png",
"128": "images/icon-128.png"
},
"background": {
"service_worker": "service-worker.js"
},
"action": {
"default_icon": {
"16": "images/icon-16.png",
"32": "images/icon-32.png",
"48": "images/icon-48.png",
"128": "images/icon-128.png"
}
},
"permissions": ["scripting", "activeTab"]
}

Popup with permissions{
"manifest_version": 3,
"name": "Popup extension that requests permissions",
"description": "Extension that includes a popup and requests host permissions and storage permissions.",
"version": "1.0",
"icons": {
"16": "images/icon-16.png",
"32": "images/icon-32.png",
"48": "images/icon-48.png",
"128": "images/icon-128.png"
},
"action": {
"default_popup": "popup.html"
},
"host_permissions": [
"https://*.example.com/"
],
"permissions": [
"storage"
]
}

Side panel{
"manifest_version": 3,
"name": "Side panel extension",
"version": "1.0",
"description": "Extension with a default side panel.",
"icons": {
"16": "images/icon-16.png",
"48": "images/icon-48.png",
"128": "images/icon-128.png"
},
"side_panel": {
"default_path": "sidepanel.html"
},
"permissions": ["sidePanel"]
}

Manifest keys

The following is a list of all supported manifest keys.

Keys required by the Extensions platform

&quot;manifest_version&quot;
An integer specifying the version of the manifest file format that your
extension uses. The only supported value is 3.
&quot;name&quot;
A string that identifies the extension in the Chrome Web
Store, the install dialog, and
the user&#39;s Chrome Extensions page (chrome://extensions). The
maximum length is 75 characters. For information on using locale-specific names,
see Internationalization.
&quot;version&quot;
A string that identifies the extension&#39;s version number. For information on
version number formatting, see Version.

Keys required by Chrome Web Store

&quot;description&quot;
A string that describes the extension on both the Chrome Web Store and the user&#39;s
extension management page. The maximum length is 132 characters. For information
on localizing descriptions, see Internationalization.
&quot;icons&quot;
One or more icons that represent your extension. For information about best
practices, see Icons.

Optional keys

&quot;action&quot;
Defines the appearance and behavior of the extension&#39;s icon in the Google
Toolbar. For more information, see chrome.action.
&quot;background&quot;
Specifies the JavaScript file containing the extension&#39;s service worker, which acts as
an event handler. For more information, see About extension service
workers.
&quot;chrome_settings_overrides&quot;
Defines overrides for selected Chrome settings. For more information, see
Overriding Chrome settings.
&quot;chrome_url_overrides&quot;
Defines overrides for default Chrome pages. For more information, see
Override Chrome pages.
&quot;commands&quot;
Defines keyboard shortcuts within the extension. For more
information, see chrome.commands.
&quot;content_scripts&quot;
Specifies JavaScript or CSS files to be used when the user opens certain web
pages. For more information, see Content scripts.
&quot;content_security_policy&quot;
Defines restrictions on the scripts, styles, and other resources an extension
can use. For more information, see Content security policy.
&quot;cross_origin_embedder_policy&quot;
Specifies a value for the Cross-Origin-Embedder-Policy HTTP header, which
configures embedding of cross-origin resources in an extension page.
&quot;cross_origin_opener_policy&quot;
Specifies a value for the Cross-Origin-Opener-Policy HTTP header, which lets
you ensure that a top-level extension page doesn&#39;t share a browsing context
group with cross-origin documents.
&quot;declarative_net_request&quot;
Defines static rules for the declarativeNetRequest
API, which allows blocking and modifying of network requests.
&quot;default_locale&quot;
A string that defines the default language of an extension that supports
multiple locales. Examples include &quot;en&quot; and &quot;pt_BR&quot;. This key is required in
localized extensions, and must not be used in extensions that aren&#39;t localized.
For more information, see Internationalization.
&quot;devtools_page&quot;
Defines pages that use the DevTools APIs.
&quot;export&quot;
Allows resources to be exported from the extension. For more information, see
Export.
&quot;externally_connectable&quot;
Specifies what other pages and extensions can connect to your extensions. For
more information, see &quot;externally_connectable&quot;.
&quot;homepage_url&quot;
A string specifying a URL for the extension&#39;s homepage. If this is undefined,
the homepage defaults to the extension&#39;s Chrome Web Store page. This field is
particularly useful if you host the extension
on your own site.
&quot;host_permissions&quot;
Lists the web pages your extension is allowed to interact with, defined using
URL match patterns. User permission for these sites is requested at install
time. For more information, see Host permissions.
&quot;import&quot;
Allows resources to be imported into the extension. For more information, see
Import.
&quot;incognito&quot;
Defines how the extension behaves in incognito mode. Supported values are
&quot;spanning&quot;, &quot;split&quot;, and &quot;not_allowed&quot;. For more information, see
Incognito.
&quot;key&quot;
Specifies your extension&#39;s ID for various development use cases. For more
information, see Key.
&quot;mime_types_handler&quot;
Registers the extension as a handler for supported MIME types, such as
application/pdf. For more information, see the
mimeHandler API.
&quot;minimum_chrome_version&quot;
Defines the oldest Chrome version that can install your extension. The value
must be a substring of an existing Chrome browser version string, such as
&quot;107&quot; or &quot;107.0.5304.87&quot;. Users with versions of Chrome older than the
minimum version see a &quot;Not compatible&quot; warning in the Chrome Web Store, and are
unable to install your extension. If you add this to an existing extension,
users whose Chrome version is older won&#39;t receive automatic updates to your
extension. This includes business users in
ephemeral mode.
&quot;oauth2&quot;
Allows the use of an OAuth 2.0 security ID. The value of this key must be an
object with &quot;client_id&quot; and &quot;scopes&quot; properties. For details, see the OAuth
2.0 tutorial.
&quot;omnibox&quot;
Allows the extension to register a keyword in Chrome&#39;s address bar. For more
information, see Omnibox.
&quot;optional_host_permissions&quot;
Declares optional host
permissions for
your extension.
&quot;optional_permissions&quot;
Declares optional permissions for your extension.
&quot;options_page&quot;
Specifies a path to an options.html file for the extension to use as an
options page. For more information, see Give users
options.
&quot;options_ui&quot;
Specifies a path to an HTML file that lets a user change extension options
from the Chrome Extensions page. For more information, see Embedded
options.
&quot;permissions&quot;
Enables use of particular extension APIs. See Permissions
for a general explanation. Reference pages for individual APIs list the
permissions they require.
&quot;requirements&quot;
Lists technologies required to use the extension. For a list of supported
requirements, see Requirements.
&quot;sandbox&quot;
Defines a set of extension pages that don&#39;t have access to extension APIs or
direct access to non-sandboxed pages. For more information, see
Sandbox.
&quot;short_name&quot;
A string containing a shortened version of the extension&#39;s name to be used
when character space is limited. The maximum length is 12 characters. If this is
undefined, a truncated version of the &quot;name&quot; key displays instead.
&quot;side_panel&quot;
Identifies an HTML file to display in a
sidePanel.
&quot;storage&quot;
Declares a JSON schema for the managed storage
area. For more
information, see Manifest for storage areas.
&quot;tts_engine&quot;
Registers the extension as a text to speech engine. For more information, see
the ttsEngine API.
&quot;update_url&quot;
A string containing the URL of the extension&#39;s updates page. Use this key if
you&#39;re hosting your extension
outside the Chrome Web Store.
&quot;version_name&quot;
A string describing the extension&#39;s version. Examples include &quot;1.0 beta&quot; and
&quot;build rc2&quot;. If this is unspecified, the &quot;version&quot; value displays on the
extension management page instead.
&quot;web_accessible_resources&quot;
Defines files within the extension that can be accessed by web pages or other
extensions. For more information, see Web Accessible
Resources.

Optional ChromeOS keys

&quot;file_browser_handlers&quot;
Provides access to the fileBrowserHandler
API, which lets extensions access the ChromeOS file browser.
&quot;file_handlers&quot;
Specifies file types for ChromeOS extensions to handle. For more information,
see file_handlers.
&quot;file_system_provider_capabilities&quot;
Allows access to the fileSystemProvider
API, which lets extensions create file systems that ChromeOS can use.
&quot;input_components&quot;
Allows the use of the Input Method Editor API. For more information, see
input_components.
