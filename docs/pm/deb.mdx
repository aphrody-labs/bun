# Debian and Ubuntu packages

`bun pm apt` and `bun pm deb` invoke the installed Linux `/usr/bin/apt-get`,
`/usr/bin/apt-cache` and `/usr/bin/dpkg-query`. APT owns repository signature
verification, freshness, package hashes, Debian dependency solving and dpkg
configuration. Bun does not embed or relicense APT/dpkg source code.

```sh
bun pm apt search curl
bun pm apt show curl
bun pm apt --root /srv/debian --simulate install curl
bun pm apt --root /srv/debian --yes install curl
bun pm apt --root /srv/debian --yes remove curl
bun pm apt --root /srv/debian update
bun pm apt --root /srv/debian list
```

Every transaction requires `--root` explicitly. A root must already contain a
Debian dpkg database (`var/lib/dpkg/status`), repository configuration and the
runtime needed by package maintainer scripts. Bun does not bootstrap a rootfs.
Use `--root /` explicitly for the host, with the host privileges required by APT.
An alternate root uses its own APT configuration, lists, cache and dpkg status;
dpkg receives `--root`, and the native dpkg executable stays on the host.

Commands: `install` (`add`), `remove` (`del`), `update`, `upgrade`, `download`,
`source`, `search`, `show` (`info`), `list` and `check`. Transaction options are
`--simulate`, `--yes`, `--download-only`, `--no-download` and
`--no-install-recommends`. Arbitrary APT options and switches disabling trust
checks are rejected. Existing repository scopes and `Signed-By` keys remain
the authority for APT trust.

`systemDependencies` accepts `deb:` and the alias `apt:`. Installation requires
`BUN_SYSTEM_ROOT` explicitly; a host installation also requires
`BUN_SYSTEM_ELEVATE=1` and actual operating system privileges. Bun does not run
sudo automatically. Resolution requires Linux APT metadata for that root.

```json
{
  "systemDependencies": {
    "deb:curl": "*"
  }
}
```

Supported constraints are `*`, `latest`, exact Debian versions and `=`, `>=`,
`<=`, `<<` or `>>` comparisons. npm semver ranges are rejected. The declared
package is locked by Debian version, architecture, archive URI and SHA-256.
Installation rechecks these against APT metadata before the transaction.
Transitive dependencies are solved and authenticated by APT; they are not
individually pinned in the current Bun lock. Read-only metadata and a successful
simulation do not prove installation.

## Local metadata planning

```sh
bun pm apt plan --packages-file Packages --release-file Release \
  --index-path main/binary-amd64/Packages --arch amd64 curl
```

This separate planner verifies a local Packages checksum against a plain
Release file and describes a limited concrete-package closure. It does not
authenticate the Release, perform a complete Debian solve, write locks or
install packages. Its JSON reports `installable: false` and the trust limits.
