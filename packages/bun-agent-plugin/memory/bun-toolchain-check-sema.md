# `bun check` — TypeScript type checker (`src/sema/`)

## What it is
- `src/sema/lib.rs` describes the crate `bun_sema` (~176k lines) as "A TypeScript type checker: resolves types on demand
 and reports TypeScript's errors by code and position". Large parts of `check` and `bind` are ports of the
 **typescript-go** checker and binder (Apache-2.0). Comments name the corresponding TS-go function, so the
 upstream function name is the search key.
- Rules and messages are TypeScript's: diagnostics are identified by TS code and position.
- Embedded `lib.*.d.ts` are stored zstd-compressed in `src/runtime/cli/typescript_libs.rs` / `.bin`. They are
 regenerated by `scripts/update-typescript-libs.ts`.

## Crate layout (`src/sema/`)
- Top level: `atom.rs` (interned names, `RecentAtoms`), `components.rs`, `config.rs` + `config_options.rs`
 (tsconfig + compiler options, `ConfigError`), `hir.rs` (the HIR the checker reads; `FileBuilder` filled by the
 parser, per-kind vectors, `ExprTag`, `FileKind`), `json.rs` (`Json`, `bigint_token_value` also used by the
 JS lexer), `local.rs`, `messages.rs` (diagnostic table, `Category`), `node.rs`, `program.rs` (`FileId`
 `Files`, `COMPARE_PATHS_CASE_SENSITIVE`, `declaration_emit_output_file_path`, `program/explain_files.rs`)
 `resolve.rs` (module resolution for the checker), `session.rs`, `table.rs`, `types.rs`, `util.rs`
 (+ `util/memory.rs`), `verify.rs`.
- `bind/` (`mod.rs`, `binder.rs`): per-file, isolated name resolution and control-flow graph (TS binder).
- `check/` (~90 files). `mod.rs` holds `Program` (shared) and per-thread checker state, `Requested`
 `FOREIGN_EVALUATION_KINDS`, `compute_ecma_line_starts`, `decode_rune`. Type queries are on demand and cached.
 Other modules:
 - `task.rs` (`Finished`, `Published`; multi-thread scheduling) and `task_tests.rs`
 - `relate.rs` / `related*.rs` (assignability)
 - `infer.rs`, `instantiate.rs`, `mapped.rs`, `unions.rs`, `flow.rs` (narrowing), `call.rs` (overload
 resolution), `expr.rs`, `decl.rs`, `decorators.rs`, `jsx.rs`, `late_bound.rs`, `alias.rs`, `symbols.rs`
 `shape.rs`
 - `print.rs` + `print_node_reuse.rs` (typeToString)
 - `explain.rs` / `explain_relation.rs` (`MessageChain`, `Explained`)
 - `grammarchecks.rs`, `regexp_scanner.rs`, `loop_cycles.rs`, `order.rs`, `spans.rs`, `sink.rs`
 - `check_source_file.rs`
 - ~35 `errors_*.rs` grouped by diagnostic family (access, assign, call, circular, classes, collisions, decl
 declaration_emit, duplicates, flow, grammar, heritage, implicit, isolated_declarations, iteration, js, jsx
 modules, names_and_exports, operators, overloads, signatures, statements, type_nodes, unused…), plus
 `errors.rs` (`Checked`).
- `driver/` (crate `bun_sema_driver`). `lib.rs`: "Type checks a project: finds its configuration and its files
 checks them on every core, and reports the errors". It is shared by `bun check`, `bun build --check` and
 `bun run --check`. It exports `CommandLine`, `CompilerOption`, `Diagnostic`, `FlagError`, `Progress`
 `RejectedFlag`, `Report`, `Request`, `ScriptKind`. Other files:
 - `host.rs` (`AlreadyRead`, `BeforeRead`, `Provided`: how file contents come in, either from disk or from
 the bundler's already-read sources)
 - `format.rs` (`Layout`, `Style`: tsc-like pretty and plain output)
- `standalone/`: the `bun-sema` binary (`main.rs`, `native.rs`). It is used by tests and for debugging dumps:
 `hir_dump.rs`, `type_writer.rs`, `symbol_writer.rs`, `visit_node.rs`. These write `.types` / `.symbols`
 baselines like TS.
- `baselines/lib.rs` runs TS conformance tests the way typescript-go does, comparing `.errors.txt` /
 `.types` / `.symbols`. It is behind the test-only `baselines` feature.

## Parser side: `src/js_parser/sema/`
- The module doc says it "Produces the input of `bun_sema`". By default the parser skips type syntax. With
 `TypeSyntax`, it also builds syntax-only `ts_syntax` nodes (`keep.rs`, `src/ast/ts_syntax.rs`).
- After the parse pass, `lower.rs` / `lower_modules.rs` / `clone_types.rs` / `builder.rs` lower the AST to the
 HIR instead of visiting it.
- The SEMA-mode AST cannot be visited. Reasons:
 - Locs may be note indices (`notes.rs`).
 - No symbols are declared.
 - Imports and exports become `S::TypeScript`.
 - Ambient and overload declarations are kept.
 - Error recovery is tolerant, like TS (`P::is_tolerant`).
- Hence **`bun build --check` parses each file twice**.
- JS files: types come from JSDoc. `jsdoc.rs` parses the tags and `reparse.rs` turns them into annotations
 casts and declarations. Other modules: `comments.rs`, `parse_declarations.rs`.
- Generic param `SEMA` on `P<'a, TYPESCRIPT, SCAN_ONLY, SEMA>` (`bun-toolchain-parser`).

## CLI: `src/runtime/cli/check_command.rs`
- `CheckCommand::exec(args) -> !` (~574) is `bun check`. With no entry point, `bun --check` is `bun check`.
 `bun --check` / `bun run --check` route there (`cli/mod.rs` ~1499).
- `check_before(entry_points, before_read) -> bool` (~691) serves `bun run --check` / `bun test --check`.
 It returns false when there are errors, and then nothing runs.
- `check_for_build_command(TypeChecked, &mut Log)` (~774) serves `bun build --check`.
 `check_for_bun_build` (~779) serves `Bun.build({ check: true })`. Both run inside the bundle once the
 bundler has read every file: `BundleV2::type_check`, `bun_bundler::options::TypeChecked`.
- Flags (`Options` struct):
 - `-p/--project` (alias `--tsconfig-override`), `-b/--build`, `--pretty` / `--no-pretty` (default depends
 on TTY), `--all` (never group identical errors), `--threads`, `--timing`, `--cwd`, `--no-emit`.
 - Unknown long flags are parsed as tsc compiler options (`--strict`, `--target es2022`, …) into
 `CommandLine`. Rejected ones are reported as `RejectedFlag`.
- Arguments.rs: `ctx.runtime_options.check` (~1261; not for the node-compat `RunAsNodeCommand`) and
 `ctx.bundler_options.check` (~2097). `bun init` can write a `bun --check` script (`init_command.rs` ~750).

## Tests (`test/cli/check/`)
- `check.test.ts`: CLI behaviour and messages. `entry-points.test.ts`: `--check` with run/build/test.
- `differential.test.ts` + `differential.ts` + `differential-cases.json` + `differential-cases-{1..4}.test.ts`
 compare against real `tsc` output.
- Conformance and typescript-go baselines are run through the `baselines` crate.
- Recent commit subjects use the prefix "`bun check`: …" (e.g. #44748, #44726).
