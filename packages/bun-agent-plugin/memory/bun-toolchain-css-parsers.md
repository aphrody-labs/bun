# CSS, data parsers, markdown, router

## `src/css/` (crate `bun_css`, ~16k lines top-level + subdirs)
- Derived from **Lightning CSS** (parcel-bundler/lightningcss, Devon Govett) + Servo `cssparser`/`selectors`
 (README.md). Via Zig port, now Rust; macros like `match_ignore_ascii_case!` re-created in `lib.rs`.
 Derive macros in `src/css_derive/`.
- `css_parser.rs` (~6k): tokenizer (`Tokenizer`, `Token`, `ParserInput`, `Parser`, `ParserState`)
 rule parsers (`TopLevelRuleParser`, `NestedRuleParser`, `StyleSheetParser`, `RuleBodyParser`
 `BundlerAtRuleParser`, `DefaultAtRule`), `StyleSheet<AtRule>` with `parse`, `parse_bundler`, `minify`
 `to_css`, `to_css_with_writer`; `StyleAttribute`; `ParserOptions`, `MinifyOptions`, `ToCssResult`
 `CssRef`, `LocalEntry`/`ComposesEntry` (CSS modules), `dtoa_short` (number serialization).
- `rules/` (one per at-rule: media, supports, keyframes, font_face, layer, container, scope
 starting_style, nesting, import, property, page, counter_style, custom_media, viewport, document
 font_palette_values, unknown, style), `selectors/` (parser.rs, selector.rs, builder.rs)
 `properties/` (`properties_generated.rs` + per-family handlers: background, border, flex, font, transform
 transition, masking, custom, css_modules, `prefix_handler.rs`…), `values/` (color incl.
 `color_generated.rs`, calc, length, gradient, image, url, ident, easing…).
- Targets / lowering: `targets.rs` (`Targets`, `Browsers`), `compat.rs` + `prefixes.rs` autogenerated by
 `build-prefixes.js` (caniuse/MDN data — do not edit by hand), `logical.rs`, `declaration.rs`
 (declaration block + handler merge), `printer.rs` (`Printer`, `PrinterOptions`, `ImportInfo`)
 `css_modules.rs` (`CssModule`, `Config`, `Pattern`, `CssModuleExport`, `CssModuleReference`)
 `dependencies.rs` (`@import`/`url` deps collected during printing), `context.rs`, `small_list.rs`.
- Bundler integration: `ParseTask` `Loader::Css` -> `StyleSheet::parse_bundler`; stored in
 `BundledAst` css column; linker passes `findImportedCSSFilesInJSOrder`, `findImportedFilesInCSSOrder`
 (`Chunk::CssImportOrder`, `Layers`), `prepareCssAstsForChunk`, `generateCompileResultForCssChunk`
 `postProcessCSSChunk`; `mangle_local_css` in LinkerContext for `.module.css`. Bundler option
 `unsupportedCSSFeatures`. See `bun-toolchain-bundler`.
- JSC bridge `src/css_jsc/`: `color_js.rs` (`Bun.color`), `css_internals.rs` (test hooks
 `minify_test_with_options`, `prefix_test_with_options`, `test_with_options`
 `minify_error_test_with_options`) exposed as `cssInternals` from `bun:internal-for-testing`.
- Tests: `test/js/bun/css/css.test.ts` (ported Lightning CSS tests via `./util.ts` helpers `cssTest`
 `minify_test`, `prefix_test`), `color.test.ts`, `css-fuzz.test.ts`, many `*-hang.test.ts` regressions;
 bundler-level `test/bundler/css/` (css-modules, wpt/) and `test/bundler/esbuild/css.test.ts`; DevServer
 `test/bake/dev/css.test.ts`.

## `src/parsers/` (crate `bun_parsers`) — all produce `bun_ast::Expr` values
- `json.rs` (JSON/JSONC) = stage 1 `json_index.rs` (SIMD structural index via Highway kernel, scalar
 fallback; byte classes generated by `scripts/build/jsonByteClass.ts`) + stage 2 `json_stage2.rs`
 (recursive descent into `E::JsonTape` rows). Module alias `json_parser`.
- `json5.rs` (token scanner + parser, spec.json5.org), `toml.rs` (TOML v1.1.0; positional scan modes;
 `lower_toml_datetimes` parser option), `yaml.rs` (~6.3k; `Parser<Enc: Encoding>` over u8/u16, labeled-
 switch loops, anchors/aliases), `xml.rs` + `xml_index.rs` (XML 1.0 non-validating, SIMD stage 1).
 Benches in `benches/`, `build.rs`.
- Consumers: bundler loaders (`Loader::{Json, Jsonc, Toml, Yaml, Json5, Xml}` -> lazy export AST)
 runtime imports, tsconfig/package.json reading, and JS APIs `Bun.JSONC`, `Bun.TOML`, `Bun.JSON5`
 `Bun.YAML`, `Bun.XML` (lazy props in `src/runtime/api/BunObject.rs`). Tests: `test/js/bun/{toml,yaml,json5}/`.
- Note: JS lexer still has JSON-mode bits (`lexer.rs` says "JavaScript/JSON lexer"); bigint tokens use
 `bun_sema::json::bigint_token_value`.

## `src/md/` (crate `bun_md`)
CommonMark/GFM markdown parser + renderers: `parser.rs`, `blocks.rs`, `containers.rs`, `inlines.rs`
`links.rs`, `ref_defs.rs`, `autolinks.rs`, `entity.rs`, `line_analysis.rs`, `html_renderer.rs`
`ansi_renderer.rs` (terminal), `root.rs` (`RenderOptions`, re-exports). Used by `Bun.markdown`
(`src/runtime/api/MarkdownObject.rs`: html/ansi/react/render), `Loader::Md` in ParseTask, `bun run file.md`
(`run_command.rs`), `pm_diff_command.rs`. Tests `test/js/bun/md/`.

## `src/router/` (crate `bun_router`, ~1.8k)
Next.js-compatible filesystem router: walks dirs via the resolver FS (`load_routes`, `load_all`), sorts
(`build_sort_table`), matches (`match_`, `match_dynamic`, `match_page_with_allocator`, `pattern_match`) with
`[param]`, `[...catchall]`, ``; defines `RouteConfig` (re-exported by
`bun_bundler::options`). JS API `Bun.FileSystemRouter` / `MatchedRoute`:
`src/runtime/api/filesystem_router.rs` + `filesystem_router.classes.ts`; test
`test/js/bun/util/filesystem_router.test.ts`. Distinct from bake's `FrameworkRouter.rs` (`bun-toolchain-bake`).
