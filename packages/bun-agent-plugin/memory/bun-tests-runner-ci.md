# CI test runner (scripts/runner.node.ts)

Related: `bun-tests-layout` · `bun-tests-patterns` · `bun-tests-harness`

## Entry points
- `scripts/runner.node.ts` (~3500 lines) is the runner; `scripts/runner.node.mjs` is a 5-line shim importing it (still used by macOS steps in `.buildkite/ci.ts`).
- package.json scripts: `test` = `node scripts/runner.node.ts --exec-path ./build/debug/bun-debug`; `test:release` (`./build/release/bun`); `node:test` = `--quiet --node-tests`; `testleak` = debug bun with `BUN_DESTRUCT_VM_ON_EXIT=1 ASAN_OPTIONS=detect_leaks=1 LSAN_OPTIONS=...suppressions=test/leaksan.supp`; `bd` = `bun scripts/build.ts --profile=debug --quiet` (build-then-exec).
- CI debugging: `bun run ci:errors | ci:status | ci:logs | ci:find | ci:watch` (`scripts/find-build.ts` over BuildKite `bk`), `bun run pr:comments`. Skill `slowest-tests`.

## Options (parseArgs)
`--exec-path` (default "bun"), `--node-tests`, `--step`, `--build-id`, `--bail`, `--shard` (default `$BUILDKITE_PARALLEL_JOB`), `--max-shards` (`$BUILDKITE_PARALLEL_JOB_COUNT`), `--include`/`--exclude` (multiple, comma lists, substring match), `--quiet`, `--smoke <fraction>`, `--vendor`, `--retries` (CI 3, local 0; N retries = N+1 attempts), `--junit`, `--junit-temp-dir`, `--junit-upload`, `--coredump-upload`, `--parallel`, `--results-json <path>`. Positionals = substring filters.

## Discovery
- `getTests(cwd)` walks `test/`, skipping hidden / `node_modules` / `node.js` dirs. `isTest` = `isNodeTest || isClusterTest || isTestStrict`.
- `isTestStrict`: JS/TS file whose basename matches `/\.test|spec\./`.
- `isNodeTest`: path contains `js/node/test/parallel/`, `js/node/test/sequential/`, or `js/bun/test/parallel/` (disabled on CI macOS x64). `isClusterTest`: `js/node/cluster/test-*.ts`.
- Sharding: LPT bin packing using `test/expected-durations.json` (`scripts/update-test-durations.mjs`).
- Vendor tests: `test/vendor.json` entries `{package, repository, tag, skipTests{glob: reason}}` cloned and run with `bun test`.

## Quarantine: test/expectations.txt
- Line format `[MODIFIERS] path/substring [EXPECTATION] # comment`; e.g. `[ WINDOWS ] test/bundler/native-plugin.test.ts [ SKIP ] # reason`.
- Any matching entry **removes the whole file** from the run (expectation kind FAIL/SKIP/CRASH/FLAKY/LEAK/TIMEOUT is parsed but ignored); substring match so a prefix quarantines a family. Use only for files that cannot run at all (hang, crash runner, trip LSan); for single broken cases use `test.skipIf/todoIf` in-file.
- Modifiers come from `getTestModifiers`: filename dash-parts (minus "bun") + os, arch, `os-arch`, distro / distro-version combos, abi (glibc/musl) / abi version combos. All modifiers are upper-cased (`getTestModifiers` returns `toUpperCase`), so entries use `WINDOWS`, `LINUX`, `DARWIN`, `X64`, `AARCH64`, `MUSL`... Entry applies if it has no modifiers or any modifier matches.

## ASAN validation lists
- When exec path contains `asan` (or locally, non-CI): sets `BUN_JSC_validateExceptionChecks=1` + `BUN_JSC_dumpSimulatedThrows=1` unless file is in `test/no-validate-exceptions.txt`.
- LeakSanitizer: `BUN_DESTRUCT_VM_ON_EXIT=1`, `ASAN_OPTIONS=allow_user_segv_handler=1:disable_coredump=0:detect_leaks=1:abort_on_error=1`, `LSAN_OPTIONS=malloc_context_size=30:print_suppressions=0:suppressions=<cwd>/test/leaksan.supp`, unless file in `test/no-validate-leaksan.txt` (~400 lines).
- ASAN runs also set `BUN_FEATURE_FLAG_NO_ORPHANS=1` and triple per-test timeout.

## Flaky / parallel
- `test/flaky-tests.txt`: path + `# reason`; only affects reporting of pass-on-retry ("flaky" vs "flaky-new"). Retries happen regardless.
- `test/parallel-allowlist.json` (generated by `scripts/update-parallel-allowlist.mjs`): dirs whose files run together in one parallel `bun test` batch; criteria: median <= 15s, no flaky annotations, not denylisted; never docker-service, stress, or cli/install tests. `test/parallel-denylist.txt` (paths relative to `test/`) = failed in batch but passed alone.

## Timeouts / spawn
- `testTimeout = 3 min` per file; `integrationTimeout = 5 min` for paths matching `integration|3rd_party|docker|bun-install-registry|bun-security-scanner-matrix|v8|bundler_compile|tonic|test/napi`. `spawnBunTest` passes `--timeout=<file timeout/2 (x3 ASAN)>` and `--reporter=dots` (+ junit when enabled), env `GITHUB_ACTIONS=true` for annotations.
- Node tests: env `FORCE_COLOR=0`, `NO_COLOR=1`, `BUN_DEBUG_QUIET_LOGS=1`, `BUN_TEST_DRAIN_EVENT_LOOP=1`; `/sequential/` gets `BUN_FEATURE_FLAG_NO_ORPHANS=1` (non-Windows); per-file timeouts via `getNodeParallelTestTimeout` (dns/cluster/docker 60s). Config `bunfig.node-test.toml` at repo root: preload `test/js/node/harness.ts` + `test/preload.ts`, `[install] auto="disable"`.
- `spawnBunTimeout = 20s` grace for exit under ASAN/LSAN.

## Run flow (`runTests`, ~line 710)
1. Read lists: `getTestExpectations`, `skipsForExceptionValidation`, `skipsForLeaksan`, flaky list, parallel allowlist.
2. `getRelevantTests(cwd, testModifiers, expectations)`: discovery -> `--include` -> `--exclude` -> expectations skip -> positional filters / `--smoke` / shard split.
3. Per file `runOneTest`: awaits napi prebuild (`awaitNapiPrebuild`) for napi files; node tests via `spawnBun` (`bun run|test --config=bunfig.node-test.toml [flags] file`), others via `spawnBunTest` (`bun test --timeout=... --reporter=dots file`).
4. `--parallel` / allowlisted dirs run as one batch; a file failing inside the batch is re-run alone and annotated "(in the parallel batch ...; passed alone)".
5. Failures retried up to `--retries`; BuildKite annotations + JUnit upload; crash/LSan output parsed into "leak of Nb in K objects" messages; coredumps uploaded on Linux.
- OS/arch helpers come from `scripts/agent.ts` (`getOs` -> darwin/linux/freebsd/windows, `getArch` -> x64/aarch64).

## Typical invocations
```sh
bun run test test/js/bun/http/serve.test.ts # runner with debug build, filter by substring
node scripts/runner.node.ts --exec-path ./build/release/bun --include cli/install
node scripts/runner.node.ts --node-tests --quiet test-fs- # ported node tests only
```

## Verifying a test locally
`bun bd test <file>` must pass; `USE_SYSTEM_BUN=1 bun test <file>` (system bun, i.e. without the change) must fail for a bug-fix test — `USE_SYSTEM_BUN` is a CLAUDE.md convention, not parsed by the runner (only two tests read it). Node ported tests: `bun bd <file>`.
